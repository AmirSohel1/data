Relationship map · entity links and cardinality

Solid lines represent actual foreign keys inside one schema. Dashed lines represent logical references between independently owned microservice databases.

Cardinality is shown only where the schema supports it. Cross-service links are conceptual references, not enforced SQL foreign keys.

Critical architecture note

AeroBook follows the database-per-service pattern. Each domain owns its own MySQL schema, so this diagram groups entities by database rather than pretending they share one relational database.

Solid FK notation is used only for relationships documented inside a single schema. Cross-service IDs are marked as logical references and are coordinated through OpenFeign REST calls, RabbitMQ events, or identity-token claims.

Schema completeness: this view includes tables and fields supported by the supplied project documentation. Some less-detailed table columns are intentionally omitted rather than invented.
