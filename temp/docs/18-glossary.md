# Domain & Technical Glossary

This glossary defines standard domain terms from commercial aviation and technical terms from cloud-native microservices architecture used throughout the AeroBook platform.

---

## 1. Aviation & Travel Domain Terminology

| Term | Definition |
|---|---|
| **PNR (Passenger Name Record)** | A unique 6-character alphanumeric identifier generated by the reservation system (e.g., `AERO9X`) that acts as the master digital record for a passenger's itinerary, ticketing, and seat assignments. |
| **IATA Airport Code** | A three-letter geocode designated by the International Air Transport Association identifying an airport (e.g., `DEL` for Delhi Indira Gandhi International, `BOM` for Mumbai Chhatrapati Shivaji Maharaj). |
| **Boarding Pass** | A physical or digital document issued during airport check-in granting a passenger permission to board an aircraft, containing passenger name, flight number, seat assignment, gate, and barcode identifier (`BP-<bookingId>-<seatNumber>`). |
| **Cabin Class** | A division of airline passenger seating with distinct pricing, baggage allowances, and amenities. AeroBook supports `ECONOMY`, `BUSINESS`, and `FIRST_CLASS`. |
| **Base Fare** | The foundational price of a flight ticket before the addition of mandatory aviation taxes, fuel surcharges, airport development fees, and promo discounts. |
| **Flight Status** | Operational state of a scheduled commercial flight: `SCHEDULED`, `ON_TIME`, `DELAYED`, `BOARDING`, `DEPARTED`, `ARRIVED`, or `CANCELLED`. |
| **Aircraft Registration** | Unique alphanumeric code identifying a civil aircraft (e.g., `VT-EXA`), analogous to an automobile license plate. In India, aircraft registrations begin with the prefix `VT-`. |
| **Manifest** | Complete passenger and crew roster on a scheduled flight used for TSA, immigration, and gate boarding audits. |
| **Gate Verification** | The process by airport operations staff scanning the passenger boarding pass barcode at the departure gate, changing their status from `CHECKED_IN` to `BOARDED`. |

## 2. Cloud & Microservices Architecture Terminology

| Term | Definition |
|---|---|
| **API Gateway** | A single perimeter reverse-proxy and routing service (`api-gateway:8083`) that acts as the single point of entry for client applications, handling SSL termination, JWT authentication, rate limiting, and request routing to downstream microservices. |
| **Service Discovery (Eureka)** | A dynamic registry (`service-discovery:8761`) where microservices register their IP addresses, ports, and operational health, enabling decoupled inter-service resolution without hardcoded network URLs. |
| **Client-Side Load Balancing** | A mechanism (via Spring Cloud LoadBalancer) where the calling microservice queries the service registry and distributes outbound HTTP requests across available healthy instances using algorithms like Round Robin. |
| **Spring Cloud OpenFeign** | A declarative REST client library allowing Java microservices to invoke remote HTTP endpoints using annotated Java interfaces rather than manual `RestTemplate` calls. |
| **Database-Per-Service** | An enterprise microservices pattern where each service strictly owns its database schema, preventing tight coupling and ensuring that data mutations can only occur via defined service APIs or event queues. |
| **AMQP (Advanced Message Queuing Protocol)** | An open standard application layer protocol for message-oriented middleware used by RabbitMQ to ensure reliable, asynchronous, decoupled message delivery between services. |
| **JWT (JSON Web Token)** | A compact, URL-safe standard (RFC 7519) representing claims transferred between parties, signed using HMAC-SHA256 to ensure authenticity and integrity without server-side session state. |
| **RBAC (Role-Based Access Control)** | An access governance approach that restricts system operations based on assigned user roles: `ROLE_USER`, `ROLE_STAFF`, and `ROLE_ADMIN`. |
| **Angular Signals** | A reactive primitive introduced in modern Angular that tracks state dependencies and performs fine-grained, surgical DOM updates without triggering full component tree change detection cycles. |
| **JaCoCo (Java Code Coverage)** | A bytecode-level code coverage library for Java that computes branch and line coverage during test execution, exporting structured reports for SonarQube ingestion. |
